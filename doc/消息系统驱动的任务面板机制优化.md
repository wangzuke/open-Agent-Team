1. Worker 进程内启动后台轮询线程

在 _run_worker_process 中，engine.run_loop() 之前启动一个 daemon 线程，每 1s 检查 inbox，消息放入 queue.Queue。

2. Engine 区分 busy/idle 状态

给 QueryEngine 加一个 threading.Event 标记当前是否在 LLM 调用中：
- run_turn() 前设为 busy
- run_turn() 返回后、下一轮开始前设为 idle
- 工具执行期间也算 busy

3. 消息注入时机

run_loop 中每轮开始时，从 queue 取出所有 pending 消息，合并注入为一条 user turn。不再靠节流时间，而是每轮都检查 queue（queue.get 是 O(1) 操作，没有 IO 开销）。

4. 任务就绪通知（关键）

当任何 agent 调用 task_update(status="completed") 时，task_update 工具自动检查：这个任务完成后，哪些下游任务的 blockedBy 全部解除了？对这些任务的 owner 发送系统消息：

"[SYSTEM] Task #{id} '{subject}' is now unblocked and ready for you to start."

这样 agent 完全不需要主动调 task_list —— 它会通过 inbox 收到"你的任务可以开始了"的通知。

整体流转

task_update(completed) 被调用
  → TaskUpdateTool 检查下游 blockedBy
  → 给下游 owner 发 inbox 消息
  → owner 的后台轮询线程 1s 内读到
  → 下一轮 idle 时注入为 user turn
  → agent 看到通知，开始工作

这样 agent 全程零主动轮询，纯消息驱动。

核心机制：
- 任务完成 → 自动通知：agent 调用 task_update(status="completed") 时，系统自动检测哪些下游任务被解锁，并发 [TASK READY] 消息到 owner 的 inbox
- 后台轮询 + 队列：daemon 线程 1s 轮询 inbox，消息放入 queue.Queue，主循环每轮 drain 注入为 [INBOX] user turn
- 预等待：worker 进程启动后先 _wait_for_actionable_task（纯 Python sleep，零 LLM 成本），直到有非 blocked 任务才进入 LLM loop
